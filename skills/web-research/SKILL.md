# Webリサーチ（裏取り付き）

事実を答えるリサーチは、必ずWebで確認してから答える。記憶だけで答えない（学習データは古い前提で扱う）。報告は、読むのがだるい人でも一瞬でわかる短さにする。

## 使うツール（Claude Code）
- **WebSearch**：まず `mode: "standard"`。結果が薄い・古い・的外れのとき、または料金・最新の出来事・ニッチな事実は最初から `"extended"`。独立した検索は同じターンでまとめて投げる。
- **WebFetch**：検索結果の要約で済ませず、根拠にする公式ページ・規約・FAQ・PDFは本文を取得して該当箇所を読む。`prompt` には「〇〇の数値と改定日を原文どおり抜き出して」のように取りたいものを具体的に書く。
- **Agent**（`run_in_background: true`）：2往復以上かかる調べものはサブエージェントに任せ、ユーザーとの会話は止めない。追加条件は **SendMessage** で同じエージェントに送る。結果が届く前に中身を推測して書かない。
- 他の環境（Cursor など）では、同等の検索・取得・作業担当の仕組みに読み替える。

## 進め方
1. **最初にひとこと返す。** 何から調べるかを一文で伝えてから始める。
2. **質問をはっきりさせる。** 曖昧な言葉（例：「営業のやつ」→営業キロ）は文脈から解釈し、解釈を一言添える。確認しないと結果が大きく変わる場合だけ聞く。
3. **調べる。** 1〜2回の検索で済むなら自分で WebSearch → WebFetch。それ以上かかるならバックグラウンドのサブエージェントに任せる（下の指示文テンプレートを使う）。
4. **ユーザー自身のサイトや記事が関係するなら、それも読む。** サイトマップや関連記事まで確認し、記事の記述と公式情報の食い違いを洗い出して、修正候補として報告する。
5. **追加の指示は同じ調査に合流させる。** 途中で条件が増えたら、新しく始め直さず進行中の調査に伝える。
6. **未確認の点は正直に書く。** 公式で確認できなかったことは「未確認」と明記し、確認先（窓口・FAQなど）を示す。
7. **メールや返信の下書きを頼まれても送らない。** 下書きを見せて、送るのはユーザー。

## サブエージェントへの指示文テンプレート
```
〇〇について調べて報告して。
- Web検索・Web取得は必須。記憶に頼らない。根拠は WebFetch で本文を読んで確かめる。
- 優先する情報源：公式サイト、規約、FAQ、公式PDF。二次情報（ブログ・まとめ）は補助。
- 調べる論点：(1)… (2)… (3)…
- 比較すべき候補：（経路・プラン・条件など）
- 今日の日付は YYYY-MM-DD。情報の掲載日・改定日も控える。
- 何も送信・投稿・購入・ログインしない。
- 報告は日本語で：結論 / 根拠と出典URL（主張ごと） / 数値の内訳 / 不確かな点・注意点。
```

## 報告の書き方（読むのがだるい人向け）
調べた量ではなく、ユーザーが次に何をすればいいかが一目でわかることを優先する。

- **1行目が答え。** はい/いいえ、数値、駅名など、それだけ読めば済む一文にする。前置き・質問の言い直し・「調べました」は書かない。
- **全体で3〜5行が目安。** 根拠は一番効くものを1〜2個だけ。残りは聞かれたら出す。
- **出典はリンク1つで。** `[ページ名](URL)` を文末に添える。URLを並べない。
- **数字は結論に効く分だけ。** 内訳が必要なら「A 42.2km＋B 27.8km＝70.0km」のように1行で。
- **見出し・太字・長い箇条書きは使わない。** 並べるものが本当に3つ以上あるときだけ短い箇条書き。
- **専門用語は言い換えるか、初出で一言説明。**
- **注意点は1つだけ。** 結論がひっくり返る可能性があるものに絞る。
- **ユーザーにやってほしいことがあれば最後に1行。** 選べるなら「`1` か `2` で」のように短く答えられる形にする。
- **長い資料（下書き・修正案・比較表）は本文に混ぜない。** 先に短い結論を送り、資料は別メッセージかファイルで渡す。

悪い例：「ご質問の件、JRの営業キロについて調べました。まず経路ですが、古河から中央本線に入るには複数のルートがあり……」
良い例：「藤野が最初です（103.5km）。相模湖は99.8kmでぎりぎり届きません。経路は南浦和・武蔵野線経由が最短です。[宇都宮線の駅一覧](URL)」

## 品質チェック（送る前に）
- 1行目だけで答えがわかるか
- 主張ごとに出典があり、その出典を実際に開いて読んだか
- 数値は内訳と合計が合っているか
- 公式情報の日付・改定時期を確認したか（今日の日付と比べて古くないか）
- 推測を事実のように書いていないか
